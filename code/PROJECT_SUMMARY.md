# Краткое описание проекта

## Назначение программной системы

Программная система предназначена для оптимального распределения мест накопления отходов между мусороперегрузочными станциями и заводами переработки. Система готовит исходные данные, рассчитывает дорожные расстояния, формирует и решает оптимизационную задачу, а затем экспортирует результаты для визуального анализа в QGIS.

Рабочая реализация приложения находится в папке `code`. Вне этой папки остаются исходные материалы УИР, справочные документы, исходные таблицы и учебный файл `trashtraining.m`, который использовался как основа для MATLAB-модели.

## Состав модулей

- `cmd/prepare-input` - Go-команда подготовки исходных XLSX-таблиц к единому CSV/JSON-формату.
- `cmd/valhalla-matrix` - Go-команда расчета матриц расстояний через локальный HTTP API Valhalla.
- `cmd/qgis-export` - Go-команда экспорта точечных и линейных GeoJSON-слоев для QGIS.
- `internal/input` - чтение, нормализация, валидация и запись подготовленных данных.
- `internal/valhalla` - HTTP-клиент Valhalla и структуры запросов/ответов matrix API.
- `internal/qgis` - формирование GeoJSON FeatureCollection для точек и линий.
- `internal/models` - общие структуры предметной области.
- `internal/utils` - общие вспомогательные функции для CSV, JSON, заголовков и числовых значений.
- `matlab` - MATLAB-компонент загрузки данных, построения оптимизационной задачи, запуска `intlinprog`, декодирования решения и сохранения результатов.

## Используемые технологии

- Go - сервисы подготовки данных, обращения к Valhalla и экспорта GeoJSON.
- MATLAB Optimization Toolbox - решение MILP-задачи через `intlinprog`.
- Valhalla - расчет дорожных расстояний между объектами.
- Docker - возможный способ запуска локального сервиса Valhalla.
- QGIS - визуализация подготовленных GeoJSON-слоев.
- CSV, JSON, GeoJSON - форматы промежуточных и выходных данных.

## Входные данные

Для полного запуска нужны исходные XLSX-таблицы:

- таблица мест накопления отходов с идентификатором, адресом, координатами, объемом контейнера, количеством контейнеров и числом вывозов в месяц;
- таблица мусороперегрузочных станций с идентификатором, названием, координатами и мощностью в тыс. тонн/год;
- таблица заводов или КПО с идентификатором, названием, координатами и мощностью в тыс. тонн/год.

При подготовке данных объем отходов переводится в тонны в год по средней плотности `0.2` т/м3, коэффициенту теплого периода `6.258` и коэффициенту холодного периода `5.7`. Мощности МПС и заводов переводятся в тонны в год умножением исходных значений на `1000`.

После работы `prepare-input` дальнейшие этапы используют подготовленные файлы:

- `data/prepared/waste_sources.csv`;
- `data/prepared/transfer_stations.csv`;
- `data/prepared/plants.csv`;
- `data/prepared/points.json`;
- `data/prepared/validation_report.json`.

Для расчета матриц также нужен запущенный локальный Valhalla API с подготовленными дорожными тайлами.

## Выходные данные

Система формирует несколько групп выходных файлов.

Подготовленные данные:

- `data/prepared/waste_sources.csv`;
- `data/prepared/transfer_stations.csv`;
- `data/prepared/plants.csv`;

## Использование результатов в QGIS

Файлы из `output/qgis` открываются в QGIS как векторные слои через `Layer -> Add Layer -> Add Vector Layer`.

Точечные слои показывают:

- места накопления отходов;
- мусороперегрузочные станции;
- заводы переработки.

Линейные слои показывают:

- назначение каждой мусорки на МПС или завод;
- потоки отходов от МПС к заводам.

Свойства объектов в GeoJSON позволяют подписывать слои, фильтровать их и анализировать объемы, расстояния и транспортные затраты.

## MATLAB-модель оптимизации

MATLAB-модель находится в папке `code/matlab`.

Ключевые файлы:

- `run_optimization.m` - полный цикл оптимизационного расчета;
- `load_input_data.m` - загрузка подготовленных CSV и матриц;
- `validate_input_data.m` - проверка размерностей, обязательных столбцов, объемов и мощностей;
- `create_variable_maps.m` - индексация переменных задачи;
- `build_problem.m` - формирование целевой функции и ограничений;
- `solve_problem.m` - запуск `intlinprog`;
- `decode_solution.m` - интерпретация найденного решения;
- `save_results.m` - сохранение результатов оптимизации.

Модель использует бинарные переменные назначения мусорок и непрерывные переменные потоков от МПС к заводам. Целевая функция минимизирует суммарные транспортные затраты на основе рассчитанных расстояний.

## Ограничения текущей реализации

- Valhalla должна быть запущена отдельно; проект не содержит готовые дорожные тайлы и Docker-конфигурацию для их сборки.
- Расстояния из матриц используются как транспортные стоимости без отдельной тарифной модели.
- Корректность результата зависит от качества координат, доступности дорожного графа и заполненности исходных таблиц.
- При наличии `NaN` в матрицах оптимизационная модель может быть не построена или не решена.
- MATLAB-расчет требует установленного Optimization Toolbox.
- GeoJSON-экспорт строит прямые линии между точками для визуализации результата, а не геометрию фактических дорожных маршрутов.
- Автоматическая стилизация слоев QGIS не входит в текущую реализацию.
